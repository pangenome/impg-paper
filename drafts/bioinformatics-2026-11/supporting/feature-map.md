## 0. Summary

impg at HEAD 0987752 lists 23 subcommands, and I group them into six subsystems.
Only the alignment-backed core (`index`, `query`, `stats`, `refine`, `align`, with `partition` as a supplement audit) carries the claim of the planned Bioinformatics paper.
The core indexes each pairwise alignment under its target and, by default, again under its query, and projects intervals through CIGARs or tracepoints, directly and through other genomes, without building a graph (NOW for CIGAR projection on synthetic PAF fixtures, CODE with 0 tests for tracepoints, src/impg.rs:1686-1712, 2379-2628).
HPRC release 2 distributes its PGGB alignments as 466 TPA files with 389,234,668 records, and no test in the repository reads a TPA or 1ALN file, so every release-scale statement waits for E1 and E2.
Local graphs from `query -o gfa` re-align the extracted intervals from scratch (src/main.rs:12324-12340, checked here), so they are graphs of new alignments, not views of a global graph.
The syncmer backend, genotyping, genome inference, `crush` and `render` are research in progress with open correctness bugs, and section 5 assigns them to later papers.
The repository holds no benchmark of impg against PGGB, Minigraph-Cactus, vg, odgi or Shredtools (phase1/evidence-inventory.md section 0 item 3).

## 2. Cross-cutting facts

### 2.1 Input formats

PAF needs 12 columns plus a `cg:Z` tag with the ops `=`, `X`, `I`, `D` and `M`, and any other op panics at query time (src/impg.rs:81-89).
PAF can be plain, BGZF (`.gz`, `.bgz`) or BGZF with a `.gzi` sidecar, and plain gzip is rejected with a bgzip hint (src/paf.rs:46-66, 272-345).
1ALN files from FastGA take sequence names from embedded GDB groups or from `.1gdb` files found by four strategies (src/onealn.rs:156-496).
TPA files come from the `tpa` crate with the record types Fastga, Standard, Variable, Mixed and FastgaNoDiff (src/tpa_parser.rs:133-244).
Index time accepts only `.paf`, `.paf.gz`, `.paf.bgz`, `.1aln` and `.tpa`, and query time treats every other name as PAF (src/alignment_record.rs:67-79, src/impg.rs:213-222).
The three formats mix in one index (src/main.rs:11646-11693), and no test covers a mixed index, which E3b needs (fix C2).
A syng prefix is the input of `query`, `partition`, `render`, `map`, `read-index`, `syng2gfa`, `syng-repair`, `genotype cos` and `genotype-infer`.
BED input does not skip `#` or `track` lines (src/commands/partition.rs:1750-1781).
The index treats names as opaque strings, and only the subset filter, `align`, `render` and the genotype code parse PanSN (src/seqidx.rs:22-35, src/subset_filter.rs:16-177, src/sequence_namespace.rs:41-56).

### 2.2 Sequence back-ends

FASTA goes through htslib faidx, which reads or creates the `.fai` and uppercases every base, so soft-masking is lost (src/faidx.rs:121-218, 204-206).
A name present in two FASTA files resolves to the last file without a warning (src/faidx.rs:155-157).
AGC goes through ragc-core, and names resolve as `contig@sample`, as a unique contig name or by the first whitespace token (src/agc_index.rs:141-229).
The AGC decompressor pool has 8 slots by default, `IMPG_AGC_DECOMPRESSOR_SLOTS` overrides it, and the thread count caps it (src/agc_index.rs:58-83).
The code comment states 3.70 GB per slot against the 3.30 GB HPRC panel and a measured 711 GB peak at 192 slots before the bound (src/agc_index.rs:86-100, checked here), so `-t 16` with 8 slots implies 29.6 GB by that comment.
Commit f259c47 reports, on CHM13#0#chr1 (248,387,328 bp), 0.4 ms per fetch for 200 random 900 B crops and for 200 random 6 KB crops, and 0.24 ms per fetch (316 MB/s) for 64 sequential 64 KB crops.
`AgcIndex::fetch_sequence` has no length guard, so an archive appended with agc older than 3.2.2 can return wrong sub-ranges with no error, and the local agc is 3.2.1 (src/agc_index.rs:383-407, untracked notes/bug-agc-appended-sample-range.md, fix C9).
One `--sequence-files` list must share one exact extension, so FASTA with AGC, `.fa` with `.fa.gz` and `.fa` with `.fasta` are all rejected (src/sequence_index.rs:49-58).
`impg align` reads FASTA only although its help text says FASTA or AGC (src/fasta.rs:8-35).

### 2.5 Determinism

The BFS applies the results of each depth in a fixed order (src/impg.rs:2379-2628).
Sequence ids come from an unseeded FxHash map, so they repeat for identical input, but they are not sorted although a comment says so (src/main.rs:11722-11735).
No test compares `query` output across thread counts, and E2 measures it at `-t` 1, 4 and 16.
`--deterministic` makes the gfasort path SGD single-threaded, the help states "+21% sort time on yeast chrV", and commit 3e44e2c gives 168.1 s with the flag vs 139.4 s without it for the final sort of a yeast chrV pggb run at `-t 12`.
Byte identity is tested only with `--deterministic`, for the `pggb` and `poa` engines on 3 x 8 kb of yeast at `-t 4`, `-t 4` and `-t 1` (tests/test_reproducible_output.rs:24-51).
The pggb engine sorts the seqwish L lines before its first sort, because seqwish emits them in thread-dependent order (src/commands/graph.rs:630-636).
`random:<frac>` pair selection hashes pairs with `std::collections::hash_map::DefaultHasher`, whose algorithm Rust does not promise to keep across releases (sweepga 4713ce0 knn_graph.rs:371-392).
`impg syng --parallel-dictionary` makes node ids independent of thread order (src/syng_parallel.rs:1-188), and `impg_seqhashCreateSafe` serializes upstream `seqhashCreate` with a mutex because it uses global `srandom` (vendor/syng/impg_syng_helpers.c:23-40).

### 2.6 Scale limits and memory

Index coordinates are i32, so a sequence longer than 2,147,483,647 bp wraps without an error (src/impg.rs:164-174, 1669-1694, fix C13).
A narrow query loads the whole tree of its target chromosome, and the loaded-tree cache has no bound (src/impg.rs:499, 1827-1888).
A single-index build of the release holds at least 389,234,668 x 56 + 778,469,336 x 48 = 59,163,669,536 bytes at once, from field sizes and before Vec growth slack and tree construction (phase2/judge-feasibility.md section 1.1, my recomputation).
The workstation had 61,478,674,432 bytes of RAM and 15,510,704,128 available at the 2026-11-08 check (plan.md section 4).
So the floor fits an idle workstation with 2,315,004,896 bytes to spare before slack, and it does not fit with the memory that other jobs held at the check.
phase2/judge-feasibility.md section 1.1 says the floor exceeds "the 57 GB of the workstation", which mixes units, because 57 GB there is 57 GiB from `free -g` and 59,163,669,536 bytes is 55.10 GiB.
The partitioned graph pipeline holds every partition GFA as a string, laces them in memory and runs gfaffix and the sort on the whole graph, with up to min(4, threads) partitions built at once (src/lib.rs:1247-1319).

### 2.12 Where competitors win today

On 92 HPRCr1 chr19 haplotypes Shredtools reports index construction 86 times faster than impg at 48 threads (the source writes the ratio with a tilde and gives the times only in its Fig. 2), and the impg time includes wfmash alignment (paper.txt:296-300).
Single-threaded, Shredtools reports 3.8 times the speed and 20 times less memory, and Shredtools at 1 thread against impg on 6% of the pairs at 48 threads gave 2 times the speed with 15 times less memory (paper.txt:300-304).
The Shredtools index is 252.4 MB on disk, against 10.1 GB for impg with all pairs (PAF plus index) and 630 MB for the 6% set (paper.txt:305-307).
Per query Shredtools took 0.484 s and 79 MB, against 4.01 s and 1.66 GB for impg on all pairs (paper.txt:309-311).
Shredtools answers queries by HTTP Range requests against a cloud-hosted index (paper.txt:25-26, 476, 501, 572), and impg has no HTTP code (phase1/odgi-shredtools.md section C item 7, decision D12).
Shredtools indexed and queried whole HPRCr1 and HPRCr2 (N = 476), and its authors could not build a comparable impg index (paper.txt:285-287).
GBZ v3 (6,398,170,680 bytes) is 3.918 times smaller than the TPA set (25,070,431,026 bytes).
PGR-TK built an index of 94 HPRC year-1 haplotypes in 18 minutes on an AWS c5.12xlarge (PMC10406601 Supplementary Table 4, phase1_research_digest.txt).
syng built a 5.8 GB GBWT of 92 human genomes in 52 min single-threaded (PMID 42878135 abstract), and impg has no build time for its HPRCv2 syng index.
In the same Shredtools benchmark, impg on the 17% pair set took 0.21 s and 12 MB per query against 0.484 s and 79 MB for Shredtools (paper.txt:309-312).
impg reports base-level interval ends, while Shredtools returns the sequence between flanking multi-MUMs with the distances to them as bounds and uses no alignment (paper.txt:278-283, 602-608).
All Shredtools numbers for impg describe impg v0.4.0 run by the Shredtools authors, and the preprint prints no impg command line (phase1_research_digest.txt).
